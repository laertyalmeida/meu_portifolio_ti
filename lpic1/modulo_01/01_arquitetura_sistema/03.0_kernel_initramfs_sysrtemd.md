# Kernel, initramfs e systemd

## Kernel

O **kernel** é o núcleo do sistema operacional.

Ele faz a comunicação entre o **hardware** e os **programas**.

Suas principais funções incluem:

* Gerenciar a CPU;
* Gerenciar a memória;
* Gerenciar dispositivos;
* Gerenciar processos;
* Gerenciar sistemas de arquivos;
* Controlar recursos do sistema.

De forma simples:

```text id="c4z7q1"
Programas
   ↓
Sistema Operacional
   ↓
Kernel
   ↓
Hardware
```

O kernel recebe solicitações dos programas e utiliza os recursos do hardware para atendê-las.

---

## Processo de inicialização

Depois que o firmware e o bootloader terminam seu trabalho, o kernel começa a ser carregado.

De forma simplificada:

```text id="8j3z1w"
BIOS / UEFI
     ↓
Bootloader
     ↓
Kernel
     ↓
initramfs
     ↓
systemd
     ↓
Serviços
     ↓
Sistema pronto
```

---

## initramfs

**initramfs — Initial RAM Filesystem**

É um pequeno sistema de arquivos criado na **memória RAM** e utilizado durante o início da inicialização do Linux.

Ele fornece ao kernel ferramentas, módulos e arquivos necessários para conseguir acessar o sistema de arquivos principal.

De forma simples:

> **O initramfs prepara o ambiente necessário para o kernel conseguir encontrar e montar o sistema Linux principal.**

---

## Por que o initramfs é necessário?

O kernel pode precisar de determinados **drivers e ferramentas** antes de conseguir acessar o sistema de arquivos principal.

Por exemplo:

```text id="a3v4q8"
Kernel
  ↓
Precisa acessar o disco
  ↓
Precisa do driver/controlador
  ↓
initramfs fornece os recursos necessários
  ↓
Sistema de arquivos principal é encontrado
```

Isso é especialmente importante quando o sistema utiliza recursos como:

* LVM;
* RAID;
* Criptografia;
* Determinados controladores de armazenamento;
* Sistemas de arquivos que precisam de módulos específicos.

---

## initrd × initramfs

Os dois termos estão relacionados ao ambiente inicial utilizado durante o boot.

### initrd

**initrd — Initial RAM Disk**

É uma abordagem mais antiga.

Utiliza uma imagem de disco carregada na RAM.

### initramfs

**initramfs — Initial RAM Filesystem**

É a abordagem moderna utilizada pelas distribuições Linux.

Em vez de funcionar como um sistema de arquivos tradicional em um dispositivo de bloco, o conteúdo é disponibilizado diretamente na RAM.

> No uso cotidiano, você pode encontrar os termos **initrd** e **initramfs** sendo utilizados de maneira semelhante, mas tecnicamente existem diferenças entre eles.

---

## systemd

O **systemd** é o sistema de inicialização e gerenciamento de serviços utilizado por muitas distribuições Linux modernas.

Depois que o kernel inicializa o sistema e o ambiente inicial termina sua função, o **systemd** assume o gerenciamento do espaço de usuário.

De forma simplificada:

```text id="6z7p1r"
Kernel
  ↓
initramfs
  ↓
systemd
  ↓
Serviços
  ↓
Sistema operacional funcionando
```

---

## PID 1

Quando o Linux termina a inicialização do kernel e começa o espaço de usuário, o primeiro processo iniciado recebe normalmente o:

```text id="d0b2na"
PID 1
```

Em sistemas que utilizam systemd:

```text id="y5e6qa"
systemd = PID 1
```

O PID 1 possui uma função muito importante porque participa do gerenciamento dos demais processos e serviços do sistema.

---

## Serviços

O systemd gerencia diversos serviços do Linux.

Exemplos:

* SSH;
* NetworkManager;
* Cron;
* Apache;
* DNS;
* DHCP;
* Outros serviços do sistema.

Cada serviço pode ser iniciado, parado, reiniciado e verificado.

Exemplo:

```bash
systemctl status ssh
```

O comando verifica o estado do serviço SSH.

Para iniciar:

```bash
systemctl start ssh
```

Para parar:

```bash
systemctl stop ssh
```

Para reiniciar:

```bash
systemctl restart ssh
```

Para habilitar a inicialização automática:

```bash
systemctl enable ssh
```

---

## Units

O systemd utiliza o conceito de **units**.

Uma unit representa um recurso que o systemd pode gerenciar.

Existem vários tipos:

* `.service` → serviços;
* `.socket` → sockets;
* `.mount` → pontos de montagem;
* `.target` → grupos ou estados de inicialização;
* `.timer` → tarefas agendadas;
* `.device` → dispositivos.

Exemplo:

```text id="h9f1j5"
ssh.service
```

É uma unit do tipo **service**.

---

## Targets

Os **targets** representam estados ou grupos de recursos que devem estar disponíveis.

Eles são semelhantes ao conceito de níveis de execução utilizado em sistemas mais antigos, mas possuem funcionamento diferente.

Exemplos:

```text id="2e8v0k"
multi-user.target
graphical.target
```

### multi-user.target

Representa um sistema em modo multiusuário, normalmente sem a necessidade de uma interface gráfica.

### graphical.target

Representa um sistema preparado para iniciar uma interface gráfica.

---

## Dependências

O systemd consegue determinar **qual serviço precisa ser iniciado antes de outro**.

Exemplo:

```text id="7x4w2q"
Rede
  ↓
Serviço que depende da rede
  ↓
Aplicação
```

Isso permite organizar a inicialização de maneira mais eficiente.

---

# Fluxo completo de inicialização

```text id="r8h2m4"
Computador ligado
       ↓
BIOS / UEFI
       ↓
POST
       ↓
Bootloader (GRUB)
       ↓
Kernel
       ↓
initramfs
       ↓
Sistema de arquivos principal
       ↓
systemd (PID 1)
       ↓
Targets e serviços
       ↓
Sistema Linux funcionando
```

## Para memorizar

> **O firmware inicia o computador, o bootloader carrega o kernel, o initramfs prepara o ambiente inicial e o systemd assume o gerenciamento do sistema.**

# Capítulo 04 – Criando o Primeiro Repositório no GitHub

---

# Neste capítulo você aprenderá

- O que é um repositório remoto.

- Quando utilizar o README, o `.gitignore` e a Licença.

---

# Objetivo

Após configurar sua conta no GitHub, o próximo passo é criar um repositório remoto.

Um repositório remoto é o local onde seu projeto ficará armazenado na internet, permitindo realizar backup, compartilhar código e sincronizar o trabalho entre diferentes computadores.

---

# O que é um Repositório?

A palavra **Repository** significa:

> **Repositório**

Um repositório é um local onde todos os arquivos e o histórico de versões de um projeto ficam armazenados.

No GitHub, os repositórios ficam hospedados na nuvem e podem ser acessados pela internet.

---

# Criando um novo repositório

Na página inicial do GitHub clique em:

**New** ou **Create repository**.

A palavra **New** significa:

> **Novo**

Já **Create repository** significa:

> **Criar repositório**

Após clicar nessa opção será exibida a tela de criação do repositório.

---

# Conhecendo cada opção

## Repository name

**Repository name** significa:

> **Nome do repositório**

É o nome que identificará seu projeto.

Exemplo:

```text
git_github
```

> **Boa prática:** utilize nomes simples, objetivos e relacionados ao conteúdo do projeto.

---

## Description

**Description** significa:

> **Descrição**

Permite adicionar uma breve explicação sobre o objetivo do repositório.

Exemplo:

```text
Documentação prática sobre Git e GitHub desenvolvida durante meus estudos.
```

A descrição é opcional, mas ajuda outras pessoas a entender rapidamente o conteúdo do projeto.

---

## Public

**Public** significa:

> **Público**

Qualquer pessoa poderá visualizar o repositório.

É a melhor opção para:

- estudos;
- portfólios;
- projetos Open Source;
- compartilhamento de conhecimento.

---

## Private

**Private** significa:

> **Privado**

Somente você e pessoas autorizadas poderão acessar o repositório.

É recomendado para:

- projetos particulares;
- documentos internos;
- códigos que ainda não devem ser publicados.

---

# Add a README file

Essa opção significa:

> **Adicionar um arquivo README**

O README é normalmente o primeiro arquivo que uma pessoa lê ao acessar um projeto.

Ele serve para apresentar informações importantes como:

- objetivo do projeto;
- conteúdo disponível;
- instruções de utilização;
- informações do autor.

Neste projeto essa opção foi deixada desmarcada, pois o repositório local já possuía um README criado anteriormente.

> **Importante:** quando o projeto já existe localmente, criar um README diretamente no GitHub pode gerar diferenças entre o repositório local e o remoto, exigindo sincronização antes do primeiro envio.

---

# Add .gitignore

Essa opção significa:

> **Adicionar um arquivo .gitignore**

O arquivo `.gitignore` informa ao Git quais arquivos ou diretórios não devem ser monitorados.

Exemplos:

- arquivos temporários;
- cache;
- arquivos de configuração local;
- ambientes virtuais;
- arquivos gerados automaticamente.

Neste projeto essa opção também foi deixada desmarcada, pois o arquivo `.gitignore` já havia sido criado durante o desenvolvimento local.

---

# Choose a license

Essa opção significa:

> **Escolher uma licença**

A licença define como outras pessoas poderão utilizar seu projeto.

Alguns exemplos conhecidos são:

- MIT
- Apache 2.0
- GPL
- BSD

Como este projeto ainda está em desenvolvimento, nenhuma licença foi selecionada neste momento.

Esse assunto poderá ser aprofundado futuramente.

---

# Criando o repositório

Após revisar todas as opções, clique em:

**Create repository**

que significa:

> **Criar repositório**

O GitHub criará seu repositório remoto e exibirá uma página com instruções para conectar um projeto existente ou iniciar um novo projeto.

Essas instruções serão utilizadas nos próximos capítulos.

---

# Boas práticas

- Escolha nomes claros para os repositórios.
- Utilize descrições objetivas.
- Crie repositórios públicos para projetos de portfólio.
- Evite criar arquivos automaticamente quando o projeto já existir localmente.
- Organize seus projetos por assunto.
